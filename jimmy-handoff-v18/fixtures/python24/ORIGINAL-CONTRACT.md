# Frozen neutral Python newline/logical contract development panel

Authored before implementation/captures. **Not a holdout, coverage estimate or substitute for original Fresh40.** `cases.jsonl` is the compact machine-readable input/expectation set; `expectations.json` repeats the same cases in readable indented form. Source is inert text. `author_panel.py` only serializes authored strings and arithmetic byte expectations; it never parses or executes the represented programs. No analyzer, scorer, tests or native job ran to author this packet.

There are24 distinct cases:8 new-contract positives,1 legacy compatibility case,6 adversarial binding/materialization cases,3 supported-prefix/unsupported-successor cases and6 semantic refusals. Positive cases are P01–P04 and P06–P09; P05 is legacy. The three added explicit-policy cases P07–P09 cover runtime-default/CRLF/CR translation, not duplicate score padding. Proof-corruption variants attached to P03 are controls, not additional coverage cases. Counts must stay separated by class and endpoint; do not sum successful truncations, logical writes, legacy closes and correct refusals into one accuracy numerator.

## Selected neutral contract

- New logical boundaries apply to **explicit** newline on w (including literal None) and initially explicit-newline r+. No-newline w keeps its legacy truncate plus close-anchored replacement. r+ starts at0 or follows a single full read and explicit seek0. Only one logical write per owned stream. No aliases, nesting, append, opaque cookies or new grammar.
- Full reads with None normalize universal newlines; full reads with empty/LF/CR/CRLF preserve decoded characters. This does not grant readline/iteration support. SourceDeclared allows distinct policies per read. Runtime default output separator is explicit neutral metadata; source-selected empty/LF preserves, CR and CRLF substitute each LF. Explicit effective-policy contradictions are refusals, not an instruction to override source.
- Every logical result has separate stream identity, source write anchor, accepted-character count, payload and ordered logical before/after content. It is not an operation-point filesystem observation. Later successful flush/close is a **future realization condition**, never an earlier completion predicate. Neither normal completion, full acceptance, successful close nor durable storage is observed.
- Source effects remain expected even when a binding/materialization probe is refused. `refusedSites` marks only the unmaterializable logical write, not a missing source effect or an unrelated successful-open truncate. P04's present empty file is distinct from B01's absent update target. B06 deliberately stores an invalid after-byte sequence as hex and requires text-preview refusal.
- `payloadHex` is the encoded **input payload before newline output translation**; `acceptedCharacterCount` counts source Unicode characters, not encoded or translated bytes. `afterHex` is the independent projected content after translation/overlay. E.g. P07 accepts2 characters, has3 payload bytes and4 after bytes. P03 accepts1 character although its payload is2 bytes.

## Byte and source proof audit

All files/reads are synthetic premises under `/authored/v17`, never host files. Hex distinguishes exact CR/LF and absent (`null`) from empty (`""`). Source spans are UTF-8 byte offsets located from independently authored tokens. Read sites use symbolic names; no native read IDs/ordinals/epochs are inferred from predictions. Native schema is deliberately not frozen here.

`requiredEarlierCompletions` lists minimum named source prerequisites. The later adapter must independently enumerate the **full** ordered predecessor inventory, including open/read/seek and prior context cleanup as required by the source, before native captures. It may not learn missing IDs/predicates from analyzer output. No exact-native-proof credit is licensed by these minimum lists alone. P03 explicitly forbids self/future predicates. A caller contract must distinguish effective-policy assertions from runtime defaults; B04/B05 contradict the former. It may not map those to harmless runtime-default overrides to turn a refusal into success.

RMW bytes are derived algebraically, not by executing Python: P01 normalizes only its first captured read; P02 overlays an8-byte shortened payload into9 original bytes and retains the last LF; P03 overlays two UTF-8 bytes; P08/P09 replace LF during output without first normalizing existing CR. No program output is used as gold. For a successful preview, the eventual adapter must check source identity, read/target/stream identity, epoch, endpoint type, character acceptance premise, payload, before/after bytes, source dependencies, exact completion inventory, replacement reconstruction and unified-diff geometry. For a typed refusal, it must require the specified layer; absence of a preview alone is not a pass.

S01–S03 require the first logical prefix to survive but reject later write/read/opaque successor effects. Cleanup bookkeeping may remain allowed; it must not emit a duplicate close-byte projection or establish a final-file claim. P03's close-failure counterfactual freezes this distinction without inventing a runtime-close-result API. S04–S09 keep nonzero seek, missing seek after read, aliases, tell cookies, nested contexts and append outside the selected contract. The optional finite lazy Boolean extension is deliberately not required by this panel; original PY08 remains a separate Fresh40 check.

Before execution, freeze an additive request adapter with exact schema, source IDs, read IDs, ordinal/epoch conventions, stream bindings/file seeds, runtime-profile meaning, source inventories and typed refusal names. Preserve this gold unchanged; if implementation cannot express a case, report a known unsupported expectation rather than converting its endpoint or dropping it. Run both baseline and candidate on identical eventual requests. Baseline inability to emit logical stream projections is missing support, not a false exact claim.
